# 问答模块 · 精卫问答（jingwei_query）

> 对应架构模块：精卫问答（问答）/ FR-QA-* + 精卫守正（合规）/ FR-CMP-*
> 代码：`backend/services/query/src/jingwei_query/`，入口 `api.query_server.main:app`，端口 8082

## 1. 职责

- 接收用户问题，执行检索增强生成（RAG）并返回答案；
- 流式输出（SSE）逐字推送；
- 多轮对话上下文与会话管理（含 guest/登录隔离与登录归并）；
- 引用溯源（标注资料来源）；
- 合规护栏（精卫守正）：不荐股、不承诺收益、无资料不编造。

## 2. 接口（main.py）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/chat/query` | 发起问答；预建 SSE 队列，执行 QueryGraph，推送 `delta`/`final`/`close` |
| GET | `/chat/stream/{session_id}` | SSE 流式输出（按 `session_id` 关联队列，`EventSourceResponse`） |
| GET | `/task/result/{task_id}` | SSE 失败兜底：直接拉取最终答案 |
| GET | `/models` | 可用对话模型列表（网关白名单公开） |
| GET | `/sessions` | 当前身份下的会话列表（`_resolve_owner` 隔离） |
| POST | `/sessions/claim` | 登录归并：把本浏览器 `anon_id` 下 guest 会话批量归并到用户 |
| GET | `/sessions/{id}/messages` | 会话消息历史 |
| PATCH | `/sessions/{id}` | 重命名会话（委托 `rename_session`） |
| DELETE | `/sessions/{id}` | 删除会话 |
| GET | `/health` | 健康检查 |

## 3. RAG 查询链（LangGraph StateGraph）

编排：`process/query_chain/`。节点（`process/query_chain/nodes/`）按顺序 fan-in 执行：

| 节点 | 职责 |
|---|---|
| `node_query_rewrite` | 查询改写（`query_rewrite_service`），提升检索召回 |
| `node_query_hyde` | HyDE：用假设性文档增强检索（可选，依赖 LLM） |
| `node_query_vector` | Milvus 向量检索（`MilvusClientWrapper.search`） |
| `node_query_rerank` | BGE-Reranker 重排（`jingwei_common.ai.reranker`） |
| `node_query_rrf` | RRF 融合多路召回结果 |
| `node_query_mcp` | 联网检索（MCP，按需；失败返回 `[]` 不阻断链路） |
| `node_query_rag` | 基于重排上下文生成答案（`query_rag_service.llm_answer`） |
| `node_query_save` | 持久化问答结果到会话历史 |

生成核心：`rag/query/answer_service.py`
- `_format_context(reranked)`：把检索结果格式化为 `[资料i](source)\n内容`，**source 即引用来源**（文件名/集合等）。
- `llm_answer(state)`：有上下文时"严格基于资料作答，无信息如实说明不编造"；无上下文时作为通用助手回答；`LLM_MOCK` 模式返回测试文案。通过 `push_to_session(session_id, "delta", {"text": ...})` 流式推送。

## 4. 会话归属与隔离（_resolve_owner）

服务端可信解析身份，**不信任客户端传参**：
- 携带有效 token → `username=真实用户`，按用户名隔离；
- 未登录 → `username="guest"`，`anon_id` 取自 `X-Anon-Id` 头或 `?anon_id=`，按浏览器隔离不同访客；
- `/sessions` 与 `/sessions/{id}/messages` 校验归属（非本人 403）；
- 登录时 `POST /sessions/claim` 调用 `claim_guest_sessions(anon_id, username)`（`jingwei_common.clients.mongo_history_utils`）批量归并，历史不丢失。

## 5. 合规护栏 · 精卫守正（FR-CMP-*）

当前后端实现为 **Prompt 层软约束 + 引用标注**（无独立硬性校验函数）：

- _不荐股、不承诺收益_：固化于 `answer_service` 的 system 原则与产品条款（`backend/README.md` 中的合规原则："不提供投资建议、不承诺收益、风险提示谨慎、不保证实时性"）。
- _引用溯源_：`_format_context` 为每段答案标注 `[资料i](source)`，输出含资料名称/类型/来源文件名，供前端展示引用。
- _无资料不编造_：prompt 明确要求"资料中没有相关信息则如实说明无法回答"。

> 演进方向（见架构文档 FR-CMP-*）：可独立 `compliance` 校验服务做硬性拦截（禁用词、收益承诺检测、荐股识别），当前为软约束。
