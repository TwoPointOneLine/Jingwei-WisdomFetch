## 1. 后端服务矩阵

后端为 `uv workspace` 多服务架构（Python + FastAPI + LangGraph），由网关统一对外暴露，各业务服务通过内部网络互通。

| 服务（代码包名） | 端口 | 入口模块 | 对应架构模块 | 职责 |
|---|---|---|---|---|
| `jingwei_gateway` | 8080 | `jingwei_gateway.api.gateway_server.main:app` | 精卫引航（网关） | 路由转发、统一鉴权、SSE 透传、静态托管前端 |
| `jingwei_auth` | 8083 | `jingwei_auth.api.auth_server.main:app` | 精卫立信（认证） | 注册、登录、Token 签发与校验、角色 |
| `jingwei_user` | 8084 | `jingwei_user.api.user_server.main:app` | 精卫明册（用户） | 用户档案、角色管理、权限边界 |
| `jingwei_knowledge` | 8081 | `jingwei_knowledge.api.import_server.main:app` | 衔文（知识构建） | 文档导入、解析、切分、向量化、入库 |
| `jingwei_query` | 8082 | `jingwei_query.api.query_server.main:app` | 精卫问答（问答） | RAG 问答、会话管理、引用溯源、合规护栏 |

> 公共底座 `jingwei_common`（`backend/packages/common`）不独立暴露，被各服务依赖。

## 3. 统一技术约定

- **框架**：FastAPI + Uvicorn；RAG / 导入流程用 LangGraph（`StateGraph`）编排。
- **统一响应**：所有接口返回 `{ code, message, data }`（`jingwei_common.web.response.ApiResponse`）。
- **异常处理**：业务异常 `jingwei_common.web.errors.ApiError`（含 `ForbiddenError` / `NotFoundError` / `BadRequestError` / `UnauthorizedError`），各服务注册 `@app.exception_handler(ApiError)` 映射 HTTP 状态。
- **鉴权**：服务间免 HTTP，直接复用 `jingwei_common.auth.AuthClient` 本地校验 token / 角色。
- **配置**：分层加载（`jingwei_common.config`），业务通过 `infra_config` / 各组单例访问；环境变量 `JINGWEI_ROOT` 为项目根定位基准。
- **向量库**：Milvus（`jingwei_common.clients.milvus_client.MilvusClientWrapper`）。
- **对象存储**：MinIO（`jingwei_common.clients.minio_client.MinioClientWrapper`，默认桶 `jingwei`）。
- **会话/历史**：MongoDB（`jingwei_common.clients.mongo_history_utils`）。

## 5. 实现状态说明

- ✅ 已实现：导入链路、RAG 问答链路、会话持久化、鉴权、路由转发、引用来源标注。
- ⚠️ 软约束：FR-CMP-* 合规护栏当前以 **Prompt 原则 + 引用标注** 实现（不荐股、不承诺收益、无资料不编造），无独立硬性校验函数；后续可演进为独立 `compliance` 校验服务（见架构文档 FR-CMP-*）。
