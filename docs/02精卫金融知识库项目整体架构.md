# 精卫 · 金融智能知识库 —— 项目整体架构

> **文档版本**：v1.0
> **依据**：[`01精卫金融知识库产品需求分析.md`](./01精卫金融知识库产品需求分析.md)（PRD v2.0，其上游为 [`00精卫金融知识库产品介绍.md`](./00精卫金融知识库产品介绍.md) v3.0）+ 公开企业级 RAG 架构实践（见附录 B）
> **定位**：本架构为**目标架构（Target Architecture）**，由 PRD 的能力域与合规约束推导而来；具体技术选型由实施团队在满足需求的前提下确定。

---

## 一、架构设计原则

架构遵循以下原则，分别对应 PRD 中的目标与合规需求：

| 原则 | 说明 | 对应 PRD |
| :--- | :--- | :--- |
| **知识锚定** | 回答必须源于检索结果，禁止脱离知识库自由生成 | FR-QA-01、QR-01 |
| **可追溯** | 每段回答可回溯至具体资料片段与来源 | FR-CITE-01、QR-01 |
| **合规前置** | 鉴权与合规护栏位于链路前端，而非事后补救 | CR-01~08、FR-COMP-* |
| **私有可控** | 支持机构内网私有化部署，数据不出域 | NFR-SEC-01、CR-05 |
| **故障隔离** | 导入、检索、生成等能力解耦，单点故障不级联 | NFR-AVAIL-01 |
| **可审计** | 关键操作留痕，满足适当性管理 | NFR-SEC-04、CR-08 |

> 行业背景：据 2025–2026 年企业级 RAG 架构综述，成熟的知识库系统普遍采用"数据工程 → 向量检索 → 智能生成 → 应用接入"的分层范式，并将网关鉴权、私有化部署作为企业落地的标准组件。本架构据此组织。

## 二、总体架构（分层视图）

精卫采用**分层 + 能力域**的总体架构，自底向上分为五层：

```
┌─────────────────────────────────────────────────────────────┐
│                      用户接入层 (Access)                       │
│    Web 前端 / 移动端(规划)  │  流式对话(SSE)  │  异常与无资料提示  │
└───────────────────────────────┬─────────────────────────────┘
                                 │ HTTPS / API
┌───────────────────────────────┴─────────────────────────────┐
│                    网关与鉴权层 (Gateway & Auth)               │
│   路由转发  │  鉴权前置  │  身份/角色(管理员/用户/访客)  │  风控网关 │
└───────────────────────────────┬─────────────────────────────┘
                                 │
┌───────────────────────────────┴─────────────────────────────┐
│                     应用能力层 (Application)                    │
│  知识构建(衔文) │ 智能问答(问答) │ 引用溯源(引源) │ 合规护栏(守正) │
└───────┬───────────────────┬───────────────────┬─────────────┘
        │                   │                   │
┌───────┴──────┐  ┌─────────┴─────────┐  ┌───────┴──────────────┐
│  检索生成层    │  │   知识处理层       │  │    治理与合规层       │
│ (Retrieve &   │  │ (Knowledge Build) │  │  (Governance)        │
│  Generate)    │  │ 解析/切分/向量化/  │  │ 提示词约束/输出校验/  │
│ 向量检索+重排 │  │ 重排/元数据管理    │  │ 标识/纠错反馈/留痕    │
└───────┬──────┘  └─────────┬─────────┘  └──────────┬───────────┘
        │                   │                   │
┌───────────────────────────┴───────────────────────────────────┘
│                        数据存储层 (Storage)                      │
│  向量库(Vector) │ 元数据/历史库(Doc/Message) │ 对象存储(Object)    │
└─────────────────────────────────────────────────────────────────┘
```

## 三、分层职责说明

### 3.1 用户接入层（Access）
- **职责**：提供对话式交互界面，承载单轮问答、多轮追问、流式输出（SSE）、历史记录、引用展示与异常提示。
- **对应 PRD**：FR-CHAT-*、NFR-USAB-*。
- **要点**：前端不持有业务逻辑，仅消费应用能力层接口；会话隔离在接入与网关层协同实现（FR-CHAT-03）。

### 3.2 网关与鉴权层（Gateway & Auth）
- **职责**：统一路由转发、鉴权前置（受保护接口需有效身份）、身份与角色管理（管理员 / 普通用户 / 访客）、敏感操作权限校验。
- **对应 PRD**：FR-AUTH-01/02、NFR-SEC-02。
- **要点**：鉴权前置于业务处理，避免越权访问；合规护栏（守正）可在网关层做第一道风险提示与禁用词拦截。

### 3.3 应用能力层（Application）
四大引擎映射（与 [`00精卫金融知识库产品介绍.md`](./00精卫金融知识库产品介绍.md) / PRD 一致）：
- **精卫衔文（知识构建）**：文档导入、状态溯源、结构化入库。→ FR-IMP-*。
- **精卫问答（智能问答）**：RAG 检索增强问答、六类查询、多轮上下文。→ FR-QA-*。
- **精卫引源（引用溯源）**：来源标注、可信呈现、回溯。→ FR-CITE-*。
- **精卫守正（合规护栏）**：禁用收益承诺、风险提示、不荐股、算法缺陷告知、标识可投诉。→ FR-COMP-*。

### 3.4 检索生成层（Retrieve & Generate）
- **职责**：执行"先检索、后生成"——基于用户问题做语义检索与重排（Rerank），召回相关资料片段，送入生成模型产出锚定知识的回答。
- **对应 PRD**：FR-QA-01、NFR-PERF-01。
- **要点**：检索与生成解耦，便于独立优化召回策略与模型（QR-01、风险"检索质量"）。

### 3.5 知识处理层（Knowledge Build）
- **职责**：文档解析、语义切分、向量化、重排模型管理、元数据（结构化字段）管理。
- **对应 PRD**：FR-IMP-01/02/03。
- **要点**：切分保留段落/条款边界，避免截断语义；同文档去重或覆盖（FR-IMP-02 AC）。

### 3.6 治理与合规层（Governance）
- **职责**：提示词约束、输出合规校验（禁用词拦截）、AI 生成标识、用户纠错反馈闭环、关键操作审计留痕。
- **对应 PRD**：FR-COMP-*、CR-06/07/08、NFR-SEC-04。
- **要点**：横切所有能力层，是"合规前置"原则的落地保障。

### 3.7 数据存储层（Storage）
- **职责**：三类存储分工——
  - **向量库**：资料片段的向量索引，支撑语义检索；
  - **元数据/历史库**：结构化字段、会话、消息、引用、用户与权限；
  - **对象存储**：原始文档文件。
- **对应 PRD**：FR-IMP-03（字段）、FR-CHAT-02（历史）、NFR-SEC-01/03（隔离与不出域）。
- **要点**：多用户数据按账号隔离，访客按设备隔离（NFR-SEC-03）。

## 四、关键数据流

### 4.1 知识导入流（衔文）
```
原始文档 → 解析 → 语义切分 → 向量化 → 向量库
                             ↓
                    结构化字段 → 元数据/历史库
                             ↓
                    原始文件 → 对象存储
```
- 失败不影响整体服务（NFR-AVAIL-01）；单文件失败可重试（FR-IMP-04）。

### 4.2 问答生成流（问答 + 引源 + 守正）
```
用户问题 → 网关鉴权 → 多轮上下文组装
        → 检索生成层：语义检索 + 重排 → 召回片段
        → 治理层：提示词约束 + 合规校验
        → 生成模型：锚定检索结果作答
        → 引源：标注来源(文件/条目/时间/产品)
        → 守正：风险提示/禁用词/算法告知
        → 流式返回前端（SSE）
```
- 检索不足 → 无资料拒答（FR-QA-05），不编造（CR-06）。

### 4.3 合规护栏流（守正，横切）
```
任意生成内容 → 输出校验：
  ├─ 命中收益承诺禁用词 → 改写/拦截（FR-COMP-01）
  ├─ 涉风险/收益 → 必带风险提示（FR-COMP-02）
  ├─ 涉买卖建议 → 退回定位边界（FR-COMP-03）
  └─ 附 AI 生成标识 + 纠错入口（FR-COMP-05）
```

## 五、非功能架构支撑

| 维度 | 架构措施 | 对应 PRD |
| :--- | :--- | :--- |
| 性能 | 检索与生成异步解耦；流式输出降低感知延迟 | NFR-PERF-01/02 |
| 可用性 | 能力层相互独立，导入异常不影响查询 | NFR-AVAIL-01 |
| 安全 | 网关鉴权前置；私有化部署；数据隔离；留痕审计 | NFR-SEC-01~04 |
| 易用 | 前端通俗呈现 + 来源可信标记 | NFR-USAB-01/02 |
| 运维 | 健康检查、日志、清晰部署指引 | NFR-OPS-01/02 |

## 六、部署架构（需求视角）

- **私有化部署**：支持机构在自有环境（内网/专有云）整体部署，资料与问答数据不出域（CR-05、NFR-SEC-01）。
- **能力域独立扩缩**：检索生成层（算力密集）与知识处理层可独立扩容，应对导入高峰与并发问答。
- **可观测**：提供健康检查与统一日志，便于监控与排障（NFR-OPS-02）。
- **部署形态**：由实施团队在满足上述需求的前提下确定（容器化 / 裸机均可）。

> 本架构不绑定具体技术栈；选型建议参考附录 B 的企业级 RAG 组件范式。
