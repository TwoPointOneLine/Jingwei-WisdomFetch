## 二、产品背景与目标

### 2.1 背景

金融机构沉淀海量非结构化文档（产品说明书、风险揭示书、招募说明书、公告、研报、FAQ 等）。普通投资者与一线业务人员难以快速、准确地获取所需信息；人工解答成本高、口径易不一致，且存在合规风险。以大模型为代表的生成式 AI 虽能生成流畅答案，但**易产生"幻觉"**，在强监管、强适当的金融场景下不可直接放任自由生成。

据 2025–2026 年企业 RAG 实践综述，RAG（检索增强生成）通过将"通用大模型"与"企业私有知识"连接，使回答准确率较纯大模型方案显著提升，已成为金融、医疗、法律等强合规垂直领域落地智能问答的主流架构——这正是精卫的产品基础（见产品介绍第三章）。

### 2.2 产品目标

| 目标 | 说明 | 关联需求 |
| :--- | :--- | :--- |
| G1 降低理解门槛 | 用通俗语言解释专业条款与术语 | FR-QA-*、FR-READ-* |
| G2 答案可追溯 | 每条回答标注来源，可回溯原文 | FR-CITE-* |
| G3 合规不编造 | 不荐股、不承诺收益、无资料拒答 | CR-*、QR-* |
| G4 对话式体验 | 自然语言提问、多轮追问、流式输出 | FR-CHAT-* |
| G5 私有化可控 | 数据不出域、模型本地化 | NFR-SEC-* |

### 2.3 产品定位（不可突破的约束）

金融知识查询与资料理解工具——**不提供个性化投资建议、不承诺收益、不替代正式产品文件或人工专业判断**（产品介绍第一章）。所有功能设计须服从此定位，并满足下述合规框架。

## 三、合规与监管框架（需求合理性依据）

本产品的合规需求并非主观约定，而是依据现行公开监管规定与行业实践推导。关键依据（详见附录 A）：

1. **《生成式人工智能服务管理暂行办法》**（国家网信办等七部门，2023-08-15 施行）：面向公众提供生成式 AI 服务，应防范传播虚假信息，对生成内容采取标识措施，建立投诉举报渠道，保护用户合法权益。→ 支撑 **CR-不编造、CR-标识可投诉、QR-真实性**。
2. **《证券期货投资者适当性管理办法》**及 **《金融机构产品适当性管理办法》**（金融监管总局，2025 年）：压实金融机构适当性管理主体责任，销售/介绍投资型产品须充分风险提示、禁止承诺保本保收益、强化"留痕"管理。→ 支撑 **CR-不承诺收益、CR-风险提示、CR-留痕**。
3. **《关于规范金融机构资产管理业务的指导意见》（资管新规）智能投顾条款**：运用 AI 开展顾问/资管业务须遵守适当性、信息披露、风险隔离，充分提示算法固有缺陷与使用风险，强化留痕。→ 支撑 **CR-不提供投资建议、CR-算法缺陷提示、CR-留痕**。
4. **行业 RAG 实践**（金融领域）：检索增强生成通过"先检索、后生成"将答案锚定在权威知识库，从源头抑制幻觉；答案须可引用、可回溯。→ 支撑 **FR-QA-RAG、FR-CITE-溯源**。
5. **2025 行业合规态势**：媒体实测显示通用大模型在金融场景"荐股""直给股票代码"已引发监管与法律争议；部分合规平台（如大智慧"慧搜"）对荐股提问直接拒绝并提示风险。→ 支撑 **CR-不提供投资建议**作为刚性边界（产品介绍第八章背景）。

## 四、用户角色与场景

### 4.1 角色（Persona）

| 角色 | 典型诉求 | 主要使用功能 |
| :--- | :--- | :--- |
| 普通投资者 | 读懂产品条款、风险、申赎规则 | 产品问答、知识问答、风险查询、业务问答 |
| 金融从业者 | 快速读懂公告、研报、政策 | 公告查询、资讯查询、多轮追问 |
| 机构管理员 | 统一知识管理、用户与权限 | 文档导入、用户管理、内容规范 |
| 系统/运维 | 部署、监控、数据安全 | 私有化部署、服务治理、留痕审计 |

### 4.2 关键场景（来自产品介绍第五章）

| 场景 | 用户动作 | 系统预期行为 |
| :--- | :--- | :--- |
| 查询产品 | "帮我介绍一下 XX 基金" | 返回基本信息、投资方向、风险等级、费用/申赎规则、主要风险、来源文件 |
| 查询风险 | "这个理财产品有什么风险？" | 风险提示（本金亏损、收益波动、流动性/市场/信用风险）+ 结合自身承受能力提示 |
| 查询概念 | "什么是净值型理财？" | 通俗解释 + 知识库注意事项 + 引用来源 |
| 查询公告 | "这份公告主要讲了什么？" | 公告核心内容总结 + 名称/时间/来源；无则明确提示 |
| 多轮追问 | "风险高吗？/ 适合稳健型吗？" | 基于上下文理解同一对象，继续基于知识库作答 |
| 无资料拒答 | 超出知识库范围 | 返回标准无资料话术，不编造 |

## 五、功能需求

### 5.1 知识构建（精卫衔文）

**FR-IMP-01 多类型文档导入** ｜ P0 ｜ 依据：产品介绍 5.1 / 6.1
- 支持金融产品资料、说明书、风险揭示书、招募说明书、公告、研报、FAQ、术语等资料的批量导入，覆盖主流文档格式。
- AC：批量导入；单文件失败不影响其余文件与整体服务；前端给出成功/失败明细。

**FR-IMP-02 解析、切分与向量化入库** ｜ P0 ｜ 依据：RAG 标准链路（产品介绍 3）
- 文档经智能解析、语义切分并向量化入库，建立可检索索引。
- AC：切分保留段落/条款边界，避免截断语义；同文档重复导入可去重或覆盖，不产生脏数据。

**FR-IMP-03 内容结构化与元数据** ｜ P1 ｜ 依据：产品介绍 6.2
- 入库内容携带结构化字段（见第七章数据模型）。
- AC：导入可接收并存储上述字段；缺失非必填字段以空值入库，不阻断。

**FR-IMP-04 导入状态与溯源** ｜ P1 ｜ 依据：产品介绍 4（衔文引擎）
- 记录导入状态（处理中/成功/失败）与来源，供前端展示与回答引用。
- AC：用户可查看已导入资料列表及状态；失败项展示原因，支持重试。

**FR-IMP-05 知识库可维护** ｜ P2 ｜ 依据：产品介绍 13（扩展）
- 支持资料更新、下线与版本管理。
- AC：下线资料不再参与检索；更新后检索结果反映最新版本。

### 5.2 智能问答（精卫问答）

**FR-QA-01 检索增强问答（RAG）** ｜ P0 ｜ 依据：产品介绍 3 / 4
- 回答基于知识库检索结果生成，先检索后生成，回答锚定检索内容。
- AC：回答中事实性陈述可在引用来源中找到对应片段；不得脱离知识库自由发挥（见 QR-真实性）。

**FR-QA-02 六类查询能力** ｜ P0 ｜ 依据：产品介绍 5.2
- 金融产品问答、金融知识问答、市场资讯查询、公司公告查询、风险提示查询、常见业务问答。
- AC：每类均可基于知识库返回结构化答案；无对应资料走无资料拒答（FR-QA-05）。

**FR-QA-03 产品结构化输出** ｜ P1 ｜ 依据：产品介绍 5.2
- 产品问答覆盖基本信息、投资与风险、规则与费用、适配与来源。
- AC：知识库含对应字段时覆盖上述维度；缺字段时说明"资料未提及"，不臆测。

**FR-QA-04 多轮追问与上下文** ｜ P0 ｜ 依据：产品介绍 4 / 9
- 基于会话上下文理解连续提问，聚焦同一产品/主题深入作答。
- AC：同会话追问可正确关联前序对象；跨会话不串上下文。

**FR-QA-05 无资料拒答** ｜ P0 ｜ 依据：产品介绍 7.2 + CR-不编造
- 检索不足时返回标准话术："当前知识库中未检索到足够信息，建议查看正式产品文件、公告原文或咨询相关工作人员。"
- AC：不编造数据/公告/条款/结论；话术可配置。

**FR-QA-06 市场/资讯不越界** ｜ P0 ｜ 依据：产品介绍 5.2（资讯查询）
- 市场资讯类回答严格基于已导入资料总结，不脱离资料自行编造市场结论。
- AC：结论均可溯源至资料；对未覆盖的最新行情/净值提示查看官方渠道（CR-不保证实时性）。

### 5.3 引用溯源（精卫引源）

**FR-CITE-01 回答标注来源** ｜ P0 ｜ 依据：产品介绍 4 / 7.1
- 每条回答返回来源文件、内容类型、产品名称/代码、发布时间、来源文件名。
- AC：引用与回答片段一一对应；用户可查看/回溯来源原文位置。

**FR-CITE-02 来源可信呈现** ｜ P1 ｜ 依据：产品介绍 11（引源命名）
- 来源以可信标记呈现，突出"可追溯"。
- AC：前端展示来源标签，可展开来源详情。

### 5.4 合规护栏（精卫守正）

**FR-COMP-01 禁用收益承诺话术** ｜ P0 ｜ 依据：CR-02 + 产品介绍 8
- 输出不得出现"一定赚钱""保证收益""保本无风险""稳赚不赔"等表达。
- AC：提示词约束 + 输出校验双重保障；命中禁用词时改写或拦截。

**FR-COMP-02 风险提示提醒** ｜ P0 ｜ 依据：CR-03 + 产品介绍 8
- 涉及风险/收益时附严谨提示："金融产品存在风险""历史业绩不代表未来表现""投资需结合自身风险承受能力"。
- AC：风险类回答 100% 携带风险提示语。

**FR-COMP-03 不提供投资建议** ｜ P0 ｜ 依据：CR-01 + 产品介绍 8
- 不指导买入/卖出/持有/赎回；仅解释资料内容（刚性边界，参照 2025 行业合规态势）。
- AC：对"该买吗？"类问题明确回应定位边界，不给出买卖建议。

**FR-COMP-04 算法缺陷与使用风险告知** ｜ P1 ｜ 依据：资管新规智能投顾条款 + 产品介绍 8
- 显著位置提示：回答由 AI 基于知识库生成，可能存在偏差，仅供参考，不构成投资建议。
- AC：每次会话/回答可见免责与风险告知；可配置展示频次。

**FR-COMP-05 内容标识与可投诉** ｜ P1 ｜ 依据：《生成式 AI 办法》+ 产品介绍 8
- 对生成内容提供来源/AI 生成标识；提供用户反馈与纠错渠道。
- AC：用户可对回答标记"不准确/有误"并提交；反馈进入治理闭环。

### 5.5 交互与前端（精卫追问 / 留痕）

**FR-CHAT-01 流式输出** ｜ P0 ｜ 依据：产品介绍 4 / 9
- 回答实时逐字呈现（流式）。
- AC：首字延迟在可接受范围；中断连接不导致服务异常。

**FR-CHAT-02 历史记录与重新提问** ｜ P1 ｜ 依据：产品介绍 9 / 11
- 用户可查看历史会话、重新发起提问。
- AC：会话按用户/访客隔离存储；可查看过往会话列表与消息。

**FR-CHAT-03 会话隔离与归并** ｜ P0 ｜ 依据：产品介绍 4（会话隔离）
- 未登录访客按设备隔离；登录用户按账号隔离；登录后未登录会话自动归并、不丢失。
- AC：不同访客互不看到对方会话；登录后历史自动归属当前账号。

**FR-CHAT-04 异常与无资料提示** ｜ P1 ｜ 依据：产品介绍 9 / 10
- 服务异常、检索失败等给出友好提示，不暴露内部错误。
- AC：提示可理解、可重试；无资料走 FR-QA-05 标准话术。

### 5.6 用户与权限

**FR-AUTH-01 注册登录与身份** ｜ P0 ｜ 依据：产品介绍 12
- 支持用户注册/登录，区分角色（管理员 / 普通用户 / 访客）。
- AC：受保护操作需有效身份；越权访问被拒。

**FR-AUTH-02 权限分级** ｜ P1 ｜ 依据：产品介绍 12 / 适当性管理主体责任
- 资料导入、用户管理、角色设置等仅限相应权限（如管理员）；普通用户仅可查询。
- AC：越权操作返回拒绝；权限边界清晰可审计。

## 七、数据模型（需求视角）

### 7.1 知识库内容实体（导入）

```json
{
  "content": "正文内容",
  "content_type": "产品说明书 / 风险提示 / 公告摘要 / FAQ / 金融术语",
  "document_title": "资料名称",
  "product_name": "产品名称",
  "product_code": "产品代码",
  "institution_name": "机构名称",
  "risk_level": "风险等级",
  "industry": "行业分类",
  "market": "市场类型",
  "publish_date": "发布时间",
  "entry_name": "条目名称",
  "source_file": "来源文件名",
  "source_path": "来源路径或资源链接"
}
```

### 7.2 会话与消息

- 会话（Session）：`id`、`owner`（用户标识 / 访客标识）、`title`、`created_at`、上下文。
- 消息（Message）：`session_id`、`role`、`content`、`citations`、`created_at`。
- 引用（Citation）：`document_title`、`content_type`、`product_name`、`product_code`、`publish_date`、`source_file`、`片段定位`。

### 7.3 用户与权限

- 用户（User）：`username`、`role`、`created_at`。
- 档案（UserProfile）：默认普通用户；特定引导账号可为管理员。

| 能力域 | 说明 | 对应功能 |

| 溯源与可信 | 来源标注、可信呈现、纠错反馈 | FR-CITE-*、FR-COMP-05 |
| 合规护栏 | 禁承诺收益、风险提示、不荐股、算法告知 | FR-COMP-* |
| 用户与权限 | 身份、分级、隔离、留痕 | FR-AUTH-*、NFR-SEC-* |
| 前端交互 | 对话、历史、异常提示 | FR-CHAT-* |

### 8.2 不在范围内（明确排除）

- 不提供个性化投资建议、不替代人工专业判断（产品定位）。
- 不保证实时行情/净值/公告的时效性（提示看官方渠道）。
- 不直接对接交易系统或执行买卖。

## 九、合规需求（强约束，P0 不可妥协）

| 编号 | 需求 | 说明 | 依据 | 关联功能 |
| :--- | :--- | :--- | :--- | :--- |
| CR-01 | 不提供投资建议 | 仅查询与解释，不指导买卖/持有/赎回 | 资管新规智能投顾条款 + 2025 合规态势 | FR-COMP-03 |
| CR-02 | 不承诺收益 | 禁用收益承诺话术，不保本保收益 | 适当性管理办法 / 资管新规 | FR-COMP-01 |
| CR-03 | 风险提示谨慎 | 必带风险与承受能力提示 | 适当性管理办法 | FR-COMP-02 |
| CR-04 | 不保证实时性 | 行情/净值/公告提示看官方渠道 | 产品介绍 8 | FR-QA-06 |
| CR-05 | 数据不出域 | 私有化部署，数据留存自有环境 | 金融数据安全要求 | NFR-SEC-01 |
| CR-06 | 不编造 | 无资料拒答，不生成虚假数据/条款/结论 | 生成式 AI 办法 + 产品介绍 7.2 | FR-QA-05 |
| CR-07 | 可标识与可投诉 | 生成内容标识 + 用户纠错反馈渠道 | 生成式 AI 办法 | FR-COMP-05 |
| CR-08 | 强化留痕 | 关键操作可审计，满足适当性管理 | 金融机构产品适当性管理办法 | NFR-SEC-04 |

## 十、质量需求

| 编号 | 需求 | 验收要点 |
| :--- | :--- | :--- |
| QR-01 真实性 | 回答有依据、来源可追溯 | 事实陈述可回溯至知识库片段（FR-QA-01/FR-CITE-01） |
| QR-02 不编造 | 无资料不编造、风险表达谨慎 | 命中 FR-QA-05 / FR-COMP-02 |
| QR-03 通俗性 | 回答易懂、术语有解释 | 用户可理解；NFR-USAB-01 |
| QR-04 及时性 | 流式输出、响应有界 | NFR-PERF-01 / FR-CHAT-01 |
| QR-05 鲁棒性 | 导入失败不影响服务、提示清楚 | FR-IMP-01 / FR-CHAT-04 |
| QR-06 一致性 | 同资料多次问答口径一致 | 基于稳定知识库与提示词 |

> 质量验证建议：建立基于知识库"标准问答对"的回归测试集，定期评测真实性、可追溯性与合规命中率。

## 十一、里程碑与优先级

### MVP（P0，必须交付）
- 知识构建（FR-IMP-01/02）

- 流式输出、多轮、会话隔离（FR-CHAT-01/03、FR-QA-04）

- 内容结构化（FR-IMP-03）、状态溯源（FR-IMP-04）
- 产品结构化输出（FR-QA-03）、来源可信呈现（FR-CITE-02）
- 历史与重新提问（FR-CHAT-02/04）、纠错反馈（FR-COMP-05）
- 权限分级（FR-AUTH-02）、留痕审计（NFR-SEC-04）

### 后续（P2，见扩展）

- 移动端、人工客服转接、知识库版本管理（FR-IMP-05）

## 十二、风险与缓解

| 风险 | 说明 | 缓解（对应需求） |
| :--- | :--- | :--- |
| 幻觉/编造 | 模型可能生成知识库外事实 | RAG 锚定 + 输出校验 + 无资料拒答（FR-QA-01/05、CR-06） |
| 合规漂移 | 模型可能越界承诺收益或荐股 | 提示词 + 输出校验双保险（FR-COMP-01/03） |
| 检索质量 | 切分/召回影响准确率 | 持续调优切块与召回策略（NFR-PERF / QR-01） |
| 时效偏差 | 知识库滞后于最新行情 | 明确不保证实时性 + 引导官方渠道（CR-04） |
| 数据合规 | 资料/问答外泄 | 私有化部署 + 数据隔离 + 留痕（NFR-SEC-01/03/04） |
