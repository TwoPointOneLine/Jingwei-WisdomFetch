# 精卫（Jingwei WisdomFetch）技术栈介绍

> *Fetching knowledge from the sea of finance.*
> 企业级私有化金融知识库 · RAG 智能问答

本文档梳理精卫的系统技术栈，供架构理解、部署评估与二次开发参考。功能需求与架构设计详见 `01 需求分析` 与 `02 整体架构`。

---

## 一、总体架构

精卫采用 **monorepo + 微服务** 架构：

- **后端**：Python（uv workspace 多模块），五大微服务 + 公共底座 `jingwei_common`。
- **前端**：React + TypeScript + Vite 单页应用（SPA）。
- **部署**：Docker 镜像 + docker compose 编排（应用服务与基础设施分离）。

后端通过**网关统一入口**对外暴露 API，前端静态产物由网关托管，整体为前后端分离、检索与生成解耦的 RAG 管线。

## 二、后端技术栈

### 2.1 语言与运行环境

| 项 | 选型 | 说明 |
|---|---|---|
| 语言 | **Python ≥ 3.11** | `requires-python = ">=3.11"` |
| 包管理 | **uv**（workspace） | 多模块工程，根在 `backend/pyproject.toml`；镜像构建用 `uv sync` 多阶段缓存 |
| Web 框架 | **FastAPI** ≥ 0.115 | 异步 ASGI，基于类型标注的路由与校验 |
| ASGI 服务器 | **Uvicorn** ≥ 0.30（`[standard]`） | 生产级运行，支持 WebSocket/SSE 依赖 |
| 流式输出 | **sse-starlette** ≥ 2.1 | 服务端推送事件（SSE），用于问答逐字流式 |
| 日志 | **loguru** ≥ 0.7 | UTF-8、结构化、自动路径定位、异步入队 |
| 配置 | **python-dotenv** | 统一读取仓库根 `.env`（`env_str/env_bool/env_int`） |

### 2.2 编排与智能体（Agentic RAG）

| 项 | 选型 | 说明 |
|---|---|---|
| 工作流编排 | **LangGraph** ≥ 0.2 | 导入链（import_chain）与查询链（query_chain）以节点图组织 |
| LLM 接入 | **LangChain** ≥ 0.3（+ `langchain-community` / `langchain-openai`） | 统一 `ChatOpenAI` 等模型抽象 |
| HTTP 客户端 | **requests** ≥ 2.31 / **httpx** | 模型与第三方 API 调用 |

### 2.3 检索与向量（Retrieval）

| 项 | 选型 | 说明 |
|---|---|---|
| 向量数据库 | **Milvus** v2.4.13（pymilvus ≥ 2.4） | 稠密 + 稀疏混合检索；standalone 模式 |
| 嵌入模型 | **BGE-M3**（FlagEmbedding ≥ 1.3 / sentence-transformers ≥ 3.0） | 多语言、稠密+稀疏+ColBERT 混合向量 |
| 重排序 | **BGE-Reranker**（FlagEmbedding） | 精排，归一化分数阈值过滤低相关候选 |
| 向量后端 | **Ollama**（默认）或 local | `BGE_M3=ollama` 走本地 Ollama `/api/embed`（GPU 加速、免 CUDA）；`local` 走 FlagEmbedding 直接加载 |
| 关键词召回 | **rank-bm25** ≥ 0.2.2 | 向量召回的回退 / 混合补充 |
| 融合策略 | **RRF**（Reciprocal Rank Fusion） | 多路召回（向量 / HyDE / 关键词）合并 |

### 2.4 大模型（LLM）

| 项 | 选型 | 说明 |
|---|---|---|
| 在线模型 | **DashScope / 通义千问**（OpenAI 兼容协议） | `qwen-plus`、`qwen-vl-max` 等，经 `OPENAI_API_KEY` 接入 |
| 本地模型 | **Ollama / LM Studio / vLLM** | `LOCAL_LLM_BASE_URL` 对接 OpenAI 兼容服务 |
| 多模态 | `qwen-vl-max` 等 | 图片/文档理解 |
| 联网检索 | **MCP（DashScope WebSearch）** | `openai-agents`（≥ 0.4.2）+ `mcp`（≥ 1.2），受 `WEB_SEARCH_ENABLED` 开关控制 |
| 调试 | `LLM_MOCK` | True 时不调远程，用于链路联调 |

### 2.5 持久化与对象存储

| 项 | 选型 | 说明 |
|---|---|---|
| 文档/聊天数据库 | **MongoDB** 7.0（pymongo ≥ 4.8） | 聊天历史、任务状态、知识库元信息、认证 token（全服务共享同一 DB） |
| 对象存储 | **MinIO** ≥ 7.2 | PDF/Markdown 原文存储；与 Milvus 内部 MinIO 端口隔离 |
| 键值/协调 | **etcd** v3.5.14 | Milvus 元数据依赖 |
| 管理台 | **Attu** v2.4.3 | Milvus Web 可视化管理（可选） |
| PDF 解析 | **MinerU**（API） | 文档结构化解析为 Markdown |

## 四、部署与运维

### 4.1 容器化

- **基础镜像**：`python:3.11-slim`，多阶段构建（builder 安装依赖 → runtime 仅拷贝 `.venv`）。
- **构建工具**：`uv` 0.7.0（多阶段依赖缓存，`UV_COMPILE_BYTECODE` 等优化）。
- **镜像仓库**：**GHCR**（GitHub Container Registry），CI/CD 推送 `jingwei-{module}:0.1.0`。

### 4.2 编排

- **应用服务**（`deploy/compose.yml`）：网关、认证、用户、知识库导入、智能问答 五个独立模块镜像，统一 `jingwei-wisdom-fetch` 网络。
- **基础设施**（`deploy/docker-compose.yml`，经 `include` 合并）：etcd、Milvus、MongoDB、MinIO（双实例：Milvus 内部 / 外部对象存储）、Attu。
- **配置来源**：仓库根 `.env`（`env_file: [../.env]`），唯一配置入口。

### 4.3 CI/CD 与质量门禁

- **CI**（`ci.yml`）：layout / lint（ruff）/ test（pytest）/ frontend（tsc + build）/ **secret-scan**（gitleaks 全历史）/ **dependency-audit**。
- **CD**（`cd.yml`）：前端构建 + 镜像构建推送 GHCR。
- **本地质量**：pre-commit（ruff / pre-commit-hooks）、gitleaks。

### 4.4 测试

- **pytest** ≥ 8 + **pytest-asyncio**（auto 模式），覆盖 `packages`、`services`。
- 前端：`tsc --noEmit` 类型检查 + 构建校验。
